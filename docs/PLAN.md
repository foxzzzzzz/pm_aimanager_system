# AI项目管理系统实施计划

## 1. 实施原则

- 严格以 `docs/PRD.md` 为产品基线，规格变化先更新PRD版本记录。
- 先定义测试，再实现功能；每个Phase验收通过后才能进入下一Phase。
- MVP只实现固定格式 `.xlsx`，不提前实现任意Excel解析。
- 解析器输出统一内部模型，核心业务不依赖Excel坐标或LLM供应商。
- 所有阈值、地址、模型和通道开关进入外部配置，不写死在代码中。
- 每个Phase完成全部自测和diff审核后，按用户授权自行提交并创建对应里程碑tag；不自动push。

## 2. 开源方案调研结论

| 项目 | 可借鉴内容 | 本项目处理方式 |
|------|------------|----------------|
| [Plane](https://github.com/makeplane/plane) | 工作项、周期、模块、状态和看板的信息组织 | 借鉴交互和领域概念，不引入其完整平台 |
| [OpenProject](https://github.com/opf/openproject) | 工作包、角色、项目计划、通知及审计 | 借鉴权限和变更追踪思路，不复用其大型单体架构 |

两者均是成熟通用项目管理平台，但本项目的差异化核心是“企业规格书导入 + 项目模板版本 + AI提案 + 微信个人触达”。MVP采用自建轻量领域模型，避免为了少量功能引入大型平台及许可证、升级和二次开发成本。进入具体模块实施前仍需对拟复用代码逐项检查许可证和维护状态。

## 3. 技术方案

### 3.1 技术栈

| 层级 | 选择 | 用途 |
|------|------|------|
| 后端 | Python 3.12、FastAPI、Pydantic、SQLAlchemy、Alembic | API、校验、领域逻辑和数据库迁移 |
| 数据库 | PostgreSQL | 项目版本、关系数据、审计和通知记录 |
| 异步任务 | Redis、Celery | Excel解析、每日扫描、消息发送与重试 |
| 管理后台 | React、TypeScript、Ant Design | 导入、差异确认、配置和审计 |
| 小程序 | 微信原生小程序、TypeScript | 登录绑定、看板、更新和消息中心 |
| 文件存储 | S3兼容对象存储（生产）/ MinIO（本地） | 原始Excel、导入报告和导出物 |
| AI | OpenAI Python SDK兼容客户端 + 内部适配层 | 标准传输、结构化输出和供应商切换 |
| 部署 | Docker Compose（开发/试点），公司VPC内生产环境 | 可重复部署和数据隔离 |

### 3.2 仓库建议结构

```text
apps/
  api/              # FastAPI
  admin-web/        # 管理后台
  mini-program/     # 微信小程序
packages/
  schemas/          # API契约/生成产物
config/
  app.example.yaml
docs/
tests/
  fixtures/         # 脱敏后的Lyra模板和变体
tmp/                # 不提交的临时文件
```

避免在MVP阶段拆分微服务。API和Worker共享同一领域代码，以部署进程区分Web请求与异步任务。

### 3.3 后端模块

- `identity`：用户、openid、手机号和项目邀请绑定。
- `projects`：项目、版本、成员、规格、里程碑和RACI。
- `imports`：模板识别、解析器注册、校验、差异和发布。
- `changes`：Excel和小程序变更提案、冲突和审批。
- `issues`：重难点问题及处理记录。
- `notifications`：规则计算、消息中心、微信和短信适配器。
- `llm`：OpenAI兼容客户端、Schema校验、提示词版本和审计。
- `audit`：不可变操作日志。

### 3.4 核心接口草案

| 方法与路径 | 用途 |
|------------|------|
| `POST /api/v1/projects` | 创建项目 |
| `POST /api/v1/projects/{id}/imports` | 上传 `.xlsx` 并创建导入任务 |
| `GET /api/v1/imports/{id}` | 查看解析、校验和差异结果 |
| `POST /api/v1/imports/{id}/publish` | 确认并发布导入版本 |
| `GET /api/v1/projects/{id}/dashboard` | 项目看板数据 |
| `POST /api/v1/milestones/{id}/progress-proposals` | 提交进度/完成/延期提案 |
| `POST /api/v1/change-proposals/{id}/approve` | 审批变更 |
| `POST /api/v1/projects/{id}/issues` | 登记问题 |
| `PATCH /api/v1/issues/{id}` | 更新问题 |
| `POST /api/v1/auth/wechat/login` | 微信登录和绑定 |
| `GET /api/v1/me/notifications` | 我的消息中心 |

写接口使用幂等键和乐观并发版本号。接口契约在实现前以OpenAPI和测试固化。

### 3.5 解析与发布流水线

```text
文件校验
  -> 模板指纹/元数据识别
  -> ParserRegistry选择解析器
  -> CanonicalProjectDraft
  -> Pydantic/业务校验
  -> 与当前ProjectVersion进行语义Diff
  -> 冲突处理
  -> 人工确认
  -> 事务发布ProjectVersion
```

解析器不能直接访问正式表执行写入。发布服务是唯一可以更新项目当前版本的入口。

### 3.6 外部配置

至少包含以下配置，并在示例文件逐项说明：

- 数据库、Redis和对象存储地址。
- Excel最大尺寸、允许扩展名和导入超时。
- `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`、超时、重试、并发和结构化输出模式。
- 微信AppID、密钥、订阅消息模板ID。
- 腾讯云短信凭证、签名、模板ID和地区。
- 时区、工作日历、每日/每周扫描时间、临期天数和升级天数。
- 通知通道开关、短信降级事件和每日发送上限。

## 4. 测试先行清单

以下用例应在对应实现代码之前建立。涉及真实手机号和微信凭证的测试使用沙箱或Mock。

### 4.1 Excel解析测试

| 编号 | 用例 | 预期 |
|------|------|------|
| XLSX-01 | 导入Lyra基准模板 | 识别模板1.0并得到完整规范模型 |
| XLSX-02 | 解析24个节点和计划版本 | 最后一条变更计划成为候选当前计划 |
| XLSX-03 | 空白与N/A | 分别得到TBD与NOT_APPLICABLE |
| XLSX-04 | 单日与日期区间 | 日期类型和边界正确 |
| XLSX-05 | RACI公式引用 | 解析为正确成员，不受公式缓存错误影响 |
| XLSX-06 | 缺少必要Sheet/表头 | 明确失败位置，不产生草稿发布 |
| XLSX-07 | `.xls`或伪装扩展名 | 拒绝上传 |
| XLSX-08 | 未知模板版本 | 拒绝并返回支持版本列表 |

### 4.2 版本与冲突测试

| 编号 | 用例 | 预期 |
|------|------|------|
| VER-01 | 相同文件重复导入 | 无业务差异，不创建重复正式版本 |
| VER-02 | Excel修改节点日期 | 展示字段级差异，确认后新版本生效 |
| VER-03 | 小程序先修改、旧Excel后导入同字段 | 标记冲突，不静默覆盖 |
| VER-04 | 取消导入 | 正式数据不变 |
| VER-05 | 发布中途异常 | 事务回滚，无部分版本 |
| VER-06 | 并发审批同一提案 | 仅一个请求成功 |

### 4.3 提醒测试

| 编号 | 用例 | 预期 |
|------|------|------|
| NTF-01 | 未来3天到期 | 生成站内临期提醒 |
| NTF-02 | 当天到期且无订阅授权 | 站内消息存在，按配置短信降级 |
| NTF-03 | 节点逾期 | 每个业务日按升级规则生成提醒 |
| NTF-04 | 节点完成/延期获批 | 旧提醒规则停止或按新日期计算 |
| NTF-05 | 任务重复执行 | 幂等键阻止重复通知 |
| NTF-06 | 微信发送失败 | 记录错误、重试并按策略降级 |
| NTF-07 | 问题解决 | 停止问题追踪提醒 |

### 4.4 AI契约测试

| 编号 | 用例 | 预期 |
|------|------|------|
| AI-01 | 供应商支持JSON Schema | 返回值通过本地Schema校验 |
| AI-02 | 供应商仅支持JSON文本 | 本地提取和校验成功 |
| AI-03 | 非法JSON/缺少字段 | 有限重试后失败，不写正式数据 |
| AI-04 | 超时或限流 | 指数退避且错误可诊断 |
| AI-05 | 切换base_url和model | 业务代码及Schema不变 |
| AI-06 | 输入包含手机号 | 发给模型前被排除或脱敏 |

### 4.5 权限与审计测试

- 非项目成员不能访问项目。
- R只能更新授权节点，不能发布Excel版本。
- 手机号和openid在日志及普通响应中脱敏。
- 每次修改可定位操作者、来源、前值、后值和项目版本。

## 5. 分阶段实施

### Phase 0：工程与文档基线

**当前状态（2026-08-06）**：已完成。工程、本地测试、容器健康检查和管理端浏览器渲染均已通过，可在首次提交确认后进入Phase 1。

**工作内容**

- 初始化Git前再次确认仓库边界，不自动提交。
- 建立后端、后台、小程序目录和统一开发命令。
- 建立配置示例、代码质量工具、测试框架和CI。
- 准备脱敏Lyra测试夹具；原始含手机号文件不得提交公共仓库。

**验收标准**

- 本地一条命令启动依赖并运行空项目。
- lint、类型检查和测试命令可重复执行。
- `.env`、`tmp/`和原始敏感文件不会被版本控制收录。

**建议里程碑**：`v0.1.0`，创建tag前必须征得用户确认。

### Phase 1：领域模型与固定模板解析

**当前状态（2026-08-06）**：已完成并通过验收，里程碑为 `v0.2.0`。

**工作内容**

- 先实现XLSX-01至XLSX-08测试和脱敏夹具。
- 建立数据库模型、迁移和CanonicalProjectDraft Schema。
- 实现模板1.0指纹、ParserRegistry和LyraTemplateV1Parser。
- 实现语义校验、Diff和导入报告。

**验收标准**

- Lyra脱敏夹具解析结果与人工基准100%一致。
- 24个节点、计划版本、空白/N/A、RACI和输出物全部通过测试。
- 无效文件不产生正式项目数据。

**建议里程碑**：`v0.2.0`。

### Phase 2：后台核心与管理端

**工作内容**

- 先实现版本、冲突、权限和审计测试。
- 实现项目、成员、规格、计划、问题和变更API。
- 实现上传、差异确认、版本发布和历史查看页面。
- 实现项目看板和问题管理。

**验收标准**

- 项目经理可完成“创建项目 -> 导入 -> 查看差异 -> 发布 -> 查看看板”。
- Excel与人工更新冲突必须显式处理。
- 关键写操作均有审计记录，权限测试通过。

**建议里程碑**：`v0.3.0`。

**当前状态（2026-08-06）**：已完成并通过验收，里程碑为 `v0.3.0`。

### Phase 3：微信小程序

**当前状态（2026-08-06）**：已完成开发环境闭环并通过验收，里程碑为 `v0.4.0`。真实微信联调仍需外部提供AppID、AppSecret和微信开发者工具，不阻塞本阶段的接口、权限与模拟登录验收。

**工作内容**

- 先实现登录绑定、项目隔离和更新授权测试。
- 实现微信登录、邀请、手机号绑定和异常审核。
- 实现我的项目、看板、节点更新、问题和消息中心。
- 实现自然语言预填接口；无法使用LLM时保留结构化表单。

**验收标准**

- 未绑定用户无法查看项目。
- R可提交本人节点完成或延期，正式更新符合审批规则。
- 小程序页面与后台当前已发布版本一致。

**建议里程碑**：`v0.4.0`。

### Phase 4：自动提醒与外部通知

**工作内容**

- 先实现NTF-01至NTF-07测试和时间边界测试。
- 实现每日/每周扫描、升级、幂等和通知记录。
- 接入微信订阅消息和腾讯云短信适配器。
- 实现发送失败、重试、降级、限额和后台诊断。

**验收标准**

- 使用可控测试时钟验证3天、当天、逾期和升级规则。
- 重跑任务不重复发送。
- 微信不可用时站内消息不丢失，关键事件按配置降级。

**建议里程碑**：`v0.5.0`。

### Phase 5：Lyra真实试点与生产准备

**工作内容**

- 在隔离环境导入真实Lyra文件并由项目经理核对。
- 邀请试点成员，验证授权、更新、提醒和问题闭环。
- 执行备份恢复、安全检查、监控告警和操作手册演练。
- 根据试点结果修正规则，不扩展任意Excel解析范围。

**验收标准**

- 连续至少两周无丢提醒、重复关键提醒或静默覆盖。
- 抽查规格、人员、节点和审计记录与人工台账一致。
- 完成回滚、备份恢复和通知通道故障演练。

**建议里程碑**：`v1.0.0`。

## 6. Phase间联合验收

- Phase 2完成后重新执行Phase 1全部导入回归测试。
- Phase 3完成后验证小程序更新与Excel重导入的冲突闭环。
- Phase 4完成后验证计划发布、完成确认、延期和问题状态对提醒的即时影响。
- Phase 5执行全量回归、权限测试、备份恢复和敏感数据检查。

## 7. 后续路线

### 7.1 标准化数据Sheet

新增 `StandardDataParser` 和标准字段字典。展示Sheet可变化，但标准化Sheet及版本保持稳定。验收重点是不同展示模板产生相同Canonical模型。

### 7.2 AI任意格式导入

新增 `AIImportParser`，输出字段映射、置信度、缺失项和冲突。所有结果进入人工确认；建立多类型历史规格书评测集后，达到约定准确率才开放使用。

### 7.3 其他集成

根据真实使用数据再评估企业微信内部群、邮件、日历、PLM/ERP和数据分析集成，不在MVP预留无实际调用的复杂代码。

## 8. 开始实施前需要的外部条件

- 微信小程序AppID、合法域名和主体权限。
- 订阅消息模板审核结果。
- 腾讯云短信签名、模板和测试额度。
- 公司VPC、PostgreSQL、Redis和对象存储环境。
- 可用于开发的脱敏Lyra Excel夹具。
- 首个OpenAI兼容LLM服务的测试密钥、base URL和模型名。
